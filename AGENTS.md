# SignSnip: agent notes

- Local web app + `signsnip` CLI for 47x70mm shelf signs. Stack: Hono API, Vite/React UI, pdf-lib, sharp, zod.
- **No real branding anywhere in the repo.** Sample brands are fake and generated by `scripts/make-fake-logos.ts`. Real data goes in gitignored `data/`.
- One renderer: `src/core/layout.ts` (pure geometry) + `src/core/pdf.ts`. The UI preview is the PDF rendered with pdf.js; never fork a second renderer.
- Batch state is `data/batch.json`, shared by CLI and UI (UI polls every 2.5s).
- Gates (check exit codes, never pipe through tail): `pnpm typecheck`, `pnpm test`, `pnpm build`.
- pnpm 11 age gate: after any `pnpm add`, check pnpm-workspace.yaml; never bypass minimumReleaseAge.
- Ports: API 7047, Vite dev 7048.
- UI = shadcn/ui (style base-nova, Base UI primitives: use `render=` not `asChild`; ToggleGroup value is an array; Select needs `items`). Components live in web/src/components/ui; add more with `pnpm dlx shadcn@latest add <name>`. components.json + vite.config.ts are at the repo root (Vite `root` is web/) so the CLI detects the framework. Registry output imports `cn` from the "cn" package; this repo rewrites it to `@/lib/utils`, so re-check after any `add`.
- Theme tokens (warm paper + orange primary) are in web/src/styles.css; no hand-written component CSS.
- Sheet geometry (`src/core/geometry.ts`) is shared by pdf.ts and the web overlay (SheetView); change cell math in one place only.
- Undo lives in web/src/useBatch.ts (snapshot stack). Toast "Undo" only undoes its own change (checks the top entry id).
- Logo scale is capped by `maxLogoScale(aspect)` (layout.ts); slider max + CLI both use it, so the control never silently does nothing.
- Background removal backs up to data/logos/originals/<id>.png; a fresh upload deletes the backup.
- Browser e2e lives outside the repo for now (Playwright from the Hermes install); run it against `pnpm start` with a fresh `data/`.
- Templates: `src/core/template.ts` is the single layout engine (PDF, designer canvas, checks). The designer measures text in the browser with Carlito via canvas (`web/src/designer/measure.ts`); keep fonts identical to the PDF's embedded ones or the canvas will lie.
- Built-in template ids `percent`/`price` can't be deleted; signs whose template is missing fall back to them. `Sign.templateId` is optional (old batches still load).
- Template-set import: same id + same layout = skipped; same design under another id = skipped ("as <id>"); otherwise keep-both (renamed copy) or replace.
- base-nova `AlertDialogAction` is a plain Button: it does NOT close the dialog. Close it yourself in onClick.
- Designer keyboard shortcuts are window-level and only active on the Templates tab; App's Ctrl+Z/Ctrl+P only on Make signs.
- Theme = Nord (web/src/styles.css). Use the --nordN variables/semantic tokens, never raw colours. Three contrast-tuned shades (--nord10-deep, --nord11-deep/-light, --nord12-deep) keep text at WCAG AA. The printed sign is always black on white paper; on-paper overlays (SignCanvas) use --nord10 directly, not --primary (which is light in dark mode). Light/system/dark toggle lives in web/src/theme.ts (localStorage signsnip.theme).
- Contrast: tests/theme-contrast.test.ts pins every token pair (text 4.5:1, control edges/focus ring 3:1, destructive on its own 10% tint, muted vs body hierarchy >= 1.25). Live check = axe sweep (signsnip skill, scripts/contrast-sweep.mjs) over 26 views x light/dark. Dark fills use bg-input/15 (not /30): --input is a 3:1 edge colour, so a heavier fill sinks text on outline buttons.
- Auto-fit (src/core/template.ts `fitSign`) is the single decision point for PDF, checks, designer canvas and the Text rules "Try a name" box: template as-is -> + abbreviations (biggest savings first, stop when readable) -> fallback template chain (same kind, max 3, no loops), each with abbreviations -> best attempt, flagged. `belowMin` only flags text that SHRANK below the minimum (designed-small text is fine). Rules live in data/rules.json (readable minimum + abbreviations); templates may override `readableMin` and set `fallbackId`.
- Batches are capped at 20 printed pages (`MAX_PAGES` in src/core/geometry.ts; copies count). `writeBatch` and the web `update()` refuse growth past it but always allow shrinking; renderPdf refuses >20 pages.
- PdfView draws only pages near the viewport (IntersectionObserver, one screen ahead) and swaps visible pages together on edits.
- Popups (select, menu, popover, autocomplete, tooltip) portal into `<div id="overlays">` inside `<main>` via `overlayRoot()` so they sit in a landmark. Remaining axe item: `aria-hidden-focus` while the collection autocomplete is open — Base UI hides the page from screen readers on purpose while its list is open (input outside popup forces its focus manager modal).
- Print/Download in the UI pass a soft gate (AlertDialog) when any sign is still below the minimum; CLI `export --strict` refuses instead.
- CLI = `src/cli/index.ts` (commands) + `help.ts` (HELP text; every command must appear there) + `shared.ts` (die/log/pick/describe) + `brands.ts` / `templates.ts` (those subcommands).
- Lookups: text a person typed (CLI args, CSV cells) goes through `brandMatches` / `templateMatches` / `savedBatchMatches` (exact id, then exact name, then partial; empty matches nothing) and `pick()`, which acts only on a single match. Ids stored on signs go through `getBrand(id)`, never a partial match, so a deleted brand shows as deleted instead of a look-alike.
- Ids from names (`idForName` in store.ts): the same name reuses its id; a different name with the same slug gets -2, -3. New ids are capped at `MAX_ID` (80, what the server accepts) with room for the suffix; longer ids already on disk stay editable. `upsertBrand` returns `created`, the single "added vs updated" decision; `addBrand` reads the logo before writing anything.
- Server guard (src/server/index.ts, `app.use("*")`): Host must be loopback (127.0.0.1, localhost, [::1]); a present Origin must be one of those on the API port or the Vite dev port 7048 (`strictPort` in vite.config.ts); a write with no Origin is refused when Sec-Fetch-Site is cross-site, or when it has neither header and a form-style body (text/plain, urlencoded, multipart). The CLI, tests and curl with application/json (or an image type for uploads) pass.
- `bin/signsnip.mjs` spawns the CLI async and forwards INT/TERM/HUP, so killing the launcher also stops `serve`.
- Hosted tabs: each tab has its own in-memory copy. OneTab (web/src/Guards.tsx) has two notices: "changed in another tab, reload" when another tab saves (BroadcastChannel), and "this tab can't save any more" with Back up + Reload when the database is closed or deleted under it (`onversionchange`/`onclose`, e.g. clear site data). Once a tab hears another tab saved, BrowserRepo writes nothing more (`otherTabSaved`), so a late autosave can't replace the newer copy; an edit still inside that tab's 300 ms autosave window is dropped. A failed IndexedDB write fires the storage-error toast and never blocks later writes; hosted Back up waits for the queue (`settled()`) and exports memory, so it works on the first click after a failure. useBatch saves at once on visibilitychange/pagehide (one keepalive PUT per batch; bodies over 60 KB in UTF-8 go without keepalive).
- Local autosave vs the server: an edit made while the server is down is kept in the tab and saved by the first poll that gets an answer (a refused batch, i.e. an HTTP error, is not retried until the next edit). Conflict rule: this tab's unsaved edit wins over a CLI change to batch.json, and a warning toast says so. Polls that started before a save finished are ignored, so they can't roll the UI back.
- Counts in words go through `count(n, noun)` in src/core/words.ts (UI and CLI); never hand-write `${n} thing${n === 1 ? "" : "s"}`. The restore dialog's summary is `describeSummary` (workspace.ts).
- Toaster offsets: pass `{ bottom: n }`, not a number; a number sets all four sides and squeezes phone toasts.
- Brands: `upsertBrand` trims names; adding an existing name (any case/spacing) updates that brand but keeps its stored name; saving by id may rename. A sign whose brand was deleted previews without a logo, and the editor says why.

## Two backends (local + hosted)
- `src/core` is platform-neutral: storage goes through `repo.ts` (`Repo` interface), images through `images.ts` (`ImageOps`), fonts through `setFontSource` in pdf.ts. `tests/core-portable.test.ts` fails if a core file imports a Node module. Only `node.ts`, `repo-fs.ts` and `paths.ts` may touch Node.
- Local: `src/core/node.ts` wires FsRepo (data/), sharp, Carlito from node_modules. The CLI and the server import it first.
- Hosted: `pnpm build:static` (VITE_SIGNO_MODE=browser) -> `web/dist-static`, relative base, no server. `web/src/local/` = IndexedDB repo (in-memory copy + background writes), canvas ImageOps, bundled fonts + seed samples. `api.ts` picks the backend; `api.init()` runs before render.
- Workspace backups (`src/core/workspace.ts`, format `signsnip/workspace` v1 (also reads the pre-rename `sign-o-matic/workspace`), logos base64): header buttons Back up (local; hosted has it in the status bar) / Restore / Start over, the hosted start page (scratch / samples / restore), and `signsnip backup|restore|start`. A backup moves freely between the local app, the CLI and the hosted app.
- `.github/workflows/pages.yml` deploys the hosted build to GitHub Pages on push to main (not yet run).
